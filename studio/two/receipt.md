**Receipt**

Exhibit two is an authored argument: Coalesce should render bounded claims, not imply resolved state. A displayed fact must disclose whether it came from an executor record, the latest-only stored-artifact lookup, a browser observation, or an unavailable write. Closure, stored status, artifact availability, and current observation remain independent. The interface refuses to manufacture liveness, causality, attempt ownership, run kinship, or archive completeness from their coincidence. Its only graph edges are explicitly inferred from recorded ordered/parallel declaration semantics.

**Result**

Declaration Job identities link directly to the existing output route when the full identity matches a Job in the run response. The complete name area is a link, with adjacent latest-attempt status available to both pointer and keyboard users. Tranches and unmatched declarations remain inert. Attempt headings use the same output address and retain the limitation that stored output cannot be selected by attempt.

Output precedes its supporting Job record. Stored and observed text remain separate surfaces, with source and attempt qualifications attached to each surface and connection state in the sticky toolbar. A stored response remains readable when the Job record or Pod tail is unavailable. Observed exits retained in the tab stay separate from recorded exit status, including after Job completion. Desktop and narrow layouts retain the same typography, tree, graph, document scrolling, and output controls.

The register separates closure from outcome. Its closure controls partition the available response into closed and unclosed records, while failed is labeled as a subset of closed. Elapsed ages are frozen at the latest HTTP read rather than ticking like proof of activity. Pipeline statements lead detail pages, opaque slugs remain labeled as addresses, and Job corroboration names the stored snapshot as its source.

Run detail puts a failed Job and its evidence address above the fold, then preserves the full assertion sequence. Log pages use document scrolling with sticky navigation instead of nesting a vertical terminal inside the page. Search names its one-hundred-record scope and recognizes the same closure vocabulary the interface displays.

Stored artifacts and browser observations resolve independently from Job closure. An unclosed Job may no longer accept a live tail while its latest-only stored endpoint already returns an artifact. The interface shows that stored evidence, states that the lookup cannot prove attempt ownership, and accounts for a failed browser request separately without filing interface copy as observed bytes.

**What became perceptible**

The latest response is a bounded 100-record window, not an archive. Its closure classes form 100 available = 95 closed + 5 unclosed; 12 failed is explicitly a subset of closed. An unclosed run may contain only closed Job rows, or a Job row with no closure. A bare stored `running` value establishes neither activity nor pod existence. All 162 Job rows in the measured window lacked recorded exit codes, so absence is shown rather than repaired with inference.

Run detail accumulates the returned assertions without folding attempts into synthetic state: executor opening, newest stored declaration, each Job attempt, and closure when present. A natural fan-out specimen exercised 19 declared objects across three nested levels and 14 Job identities. The recorded nested list remains authoritative; a sibling Job-only graph makes its inferred split, branch asymmetry, and join perceptible without presenting tranche objects as executions. Pipeline prose carries recognizable meaning; the literal slug remains continuously labeled as the stable address.

Log detail now permits both custodies to be true. A stored artifact is exact text from the latest addressable run/Job/container lookup. A tail is a separate observation made by this browser. An ended tail is kept in `sessionStorage` for the tab page session, survives reload and same-tab navigation, is normally cleared with the tab, and never becomes a Coalesce record. An unavailable tail with zero received lines has no byte meter or copy surface; the interface’s explanation is explicitly not evidence.

**Judgment**

The global claim key remains visible narrowly because its learned grammar is useful even though every marker is also word-paired. Unclosed elapsed values carry a leading `+` and a duration label so they do not masquerade as clock time. Response counts state their arithmetic, failed evidence opens at its causal end, and unavailable values use words instead of ambiguous punctuation.

The initial detail read for each unclosed register row is a deliberate, bounded cost: the list contract cannot otherwise reveal the Job/run closure discrepancy. It does not poll. Duplicate initial reads and tail connections under the development server come from React StrictMode’s development remount and do not occur in the production bundle. Run families, sibling navigation, Kubernetes object identities, and causal summaries remain absent because neither the API nor the observed payload supplies those relations. Meaningful pipeline prose leads while the opaque slug remains explicit as the address.
